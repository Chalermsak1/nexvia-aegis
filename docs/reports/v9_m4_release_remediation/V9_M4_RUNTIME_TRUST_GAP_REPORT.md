# V9-M4 runtime trust gap report (SEC-02)

**Prepared:** 2026-10-27 (Asia/Bangkok). **Status:** BLOCKED; `GATE_B_NOT_AUTHORIZED`. This is a technical gap analysis, not an approval or a change to production controls. Source inventory and exact observed commands are in `V9_M4_PACKAGE_RUNTIME_PROVENANCE_INVENTORY.md`.

## Trust claim tested

The signed-ticket contract requires Python `3.12.14`, an approved-commit lockfile and installed packages matching recorded wheel hashes (`docs/architecture/v9_m4_signed_gate_b_ticket_implementation_contract.md:424-440`). The current implementation authenticates **local consistency**: lock bytes against caller-supplied expected digest, interpreter location, isolated Python, dependency versions, local RECORD file hashes and selected import origins (`src/nexvia_aegis/security/runtime_integrity.py:147-242`). It explicitly reports `wheel_archive_sha256_verified: false` (`:232`). A read-only direct probe in the engineering checkout passed those local checks for 34 packages and returned that flag as false (inventory, “Actual runtime” section). The contract phrase “recorded wheel hashes” is therefore **not demonstrated** by the current verifier. No independent owner-pinned package archive or equivalent attestation was found in the inspected repository material (`docs/reports/v9_m4_release_remediation/V9_M4_OWNER_DECISION_REGISTER.md:157-164`; `V9_M4_STAGING_MANIFEST_DRAFT_UNAPPROVED.md:45-46`).

## Proposed closure sequence — requires owner/security approval

1. **Owner and security reviewer choose the trust boundary.** Option A is an owner-protected offline wheelhouse; Option B is a separately authenticated signed build/install attestation with equivalent complete archive coverage. The current lock/RECORD-only option cannot establish package origin (`V9_M4_OWNER_DECISION_REGISTER.md:159-164`). Specify who can publish, rotate and revoke the pins, and which machine/account verifies them.
2. **Reconcile lock identity and candidate scope.** Record exact candidate SHA, lock raw digest, interpreter binary identity, OS/architecture and selected dependency closure. Identify whether build tools and the project package are in scope. The staging draft leaves these fields unset (`V9_M4_STAGING_MANIFEST_DRAFT_UNAPPROVED.md:41-49`).
3. **Implement only after approval.** An engineering change would verify authenticated archive digests before creating a clean, candidate-specific environment; then run the existing isolated installed-state probe and record both archive provenance and installed-state evidence before any ticket claim. Preserve failure logs and never reinterpret `wheel_archive_sha256_verified=false` as success. This report does **not** implement the change.
4. **Synthetic regression boundary.** Use temporary benign wheels and an independently held fixture pin, never production tickets or Holdout inputs. Reject modified bytes with unchanged version, changed RECORD matching changed installed file, extra package, missing package, wrong platform, wrong interpreter (including same version from wrong binary/path), stale editable origin, unexpected import, unavailable trusted inventory, and interrupted environment build. Assert failure precedes any ledger claim and retains evidence. A positive fixture must bind the exact wheel digest, runtime and checkout.

**Current decision:** SEC-02 is not closed. Local hashes, lock metadata, installed RECORD and version strings support drift detection but cannot serve as their own authenticity anchor. No Gate B authorization, confirmatory result, or release-ready claim follows from this report.
